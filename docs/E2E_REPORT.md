## Что нашлось в ходе проверки

1. **Ошибка в первом варианте сценария, не в системе.** Шаг «блокировка инспектора с делами запрещена» стоял после архивирования. К этому моменту активных дел у инспектора не было, и система правильно разрешила блокировку. Это ломало следующие прогоны. Шаги администратора перенесены до архивирования, а сам шаг теперь ещё проверяет, что статус остался «Активен».
2. **Основная база 10.100.200.151 временно недоступна.** Во время проверки база дважды переставала отвечать, и вход на `:8000` зависал в ожидании подключения. Пока базы не было, сценарий прошёл на изолированном стенде (SQLite, те же учётные записи): 44 шага выполнены, 2 шага API ДТП пропущены, потому что ДТП-эндпоинтов на стенде нет. После восстановления базы проведён полный прогон, описанный в этом отчёте.
3. **Ошибок в коде «Опеки» не найдено.**

## Очистка

Все записи прогона помечены «ТЕСТ Е2Е» и удалены командой бэкенда:

```sh
python manage.py purge_opeka_e2e        # показать, что будет удалено
python manage.py purge_opeka_e2e --yes  # удалить
```

Удалено: 2 дела, 7 документов (вместе с файлами), 1 временный пользователь, 1 тестовое ОВД. После очистки в «Опеке» 0 дел, 7 тестовых учётных записей активны, справочник ОВД в исходном виде.
