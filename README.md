# Опека — реестр и надзор (Next.js)

Фронтенд реестра дел несовершеннолетних. Дизайн взят из дашборда `prosecutor_dtp_next`: те же цветовые токены, боковое меню, KPI-плитки, таблицы, светлая и тёмная темы. Данные, вход и права хранятся в `prosecutor-backend` (приложение `prosecutor_opeka`, см. его README).

Это отдельный проект, не связанный с ДТП-дашбордом.

## Запуск

```sh
yarn                 # установка зависимостей (yarn.lock, как в prosecutor_dtp_next)
yarn dev             # http://localhost:3000
yarn build && yarn start
```

Переменные в `.env.local` (образец — `.env.example`):

- `NEXT_PUBLIC_BACKEND_API_URL` — адрес prosecutor-backend без слэша на конце, например `https://pros-admin.smartalmaty.kz`;
- `NEXT_PUBLIC_MAPBOX_TOKEN` — публичный pk-токен для карты на странице входа. Без него страница работает, просто без карты.

Обе переменные встраиваются в сборку, поэтому после их изменения нужна пересборка. Docker:

```sh
docker build --build-arg NEXT_PUBLIC_BACKEND_API_URL=https://… --build-arg NEXT_PUBLIC_MAPBOX_TOKEN=pk.… -t opeka-next .
docker run -p 3000:3000 opeka-next
```

**Локально без доступа к основной базе:** в бэкенде есть стенд на SQLite (см. «Тесты» в `prosecutor_opeka/README.md`). Поднимите его на `:8001` и укажите `NEXT_PUBLIC_BACKEND_API_URL=http://localhost:8001`.

## Вход

Страница `/login` повторяет страницу входа ДТП-дашборда: приглушённое видео слева, форма на тёмной карте справа. Если в системе включено «уменьшить движение», вместо видео показывается неподвижная карта районов Алматы.

Вход идёт через общую авторизацию платформы (`/api/v1/auth/login/`, JWT, токены в `localStorage`, как в ДТП). Затем приложение запрашивает рабочее пространство. Если у учётной записи нет профиля «Опеки», показывается «У учётной записи нет доступа к «Опеке»», и сессия не сохраняется.

Без входа любой адрес ведёт на `/login?next=…`, после входа пользователь возвращается на запрошенную страницу (только внутренние адреса). После «Выйти» открывается чистый `/login`, а refresh-токен отзывается на сервере.

Демо-профили для тестового стенда создаёт `manage.py seed_opeka --demo --password …`: `opeka.sadykova`, `opeka.omarov`, `opeka.akhmetov` (инспекторы), `opeka.nurlanov` (руководитель), `opeka.seitova` (прокурор), `opeka.admin`.

## Что умеет

| Роль | Разделы |
|---|---|
| Инспектор | Реестр дел (свои карточки), Сигналы надзора |
| Руководитель ОВД | Обзор подразделения, Реестр, Сигналы (входящие/отправленные), Задачи и сроки |
| Городской прокурор | Общий обзор, Реестр (весь город) |
| Администратор | Пользователи (создание учётных записей с профилем), Справочники |
| Суперадминистратор (суперпользователь Django) | Все разделы: обзор и реестр всего города, сигналы, задачи, пользователи, справочники |

- Карточка дела с вкладками «Основные сведения», «Документы» и «Комментарии и замечания». Документы скачиваются с сервера по токену; PDF и картинки можно открыть в новой вкладке.
- Цикл замечания: направить → исправить → принять или вернуть; автор может отменить; руководитель может передать замечание прокурора инспектору.
- Архивирование с рассмотрением у руководителя своего ОВД, отметка «Проверено», смена инспектора, экспорт реестра в CSV с защитой от формул.

## Устройство

```
lib/
  api.ts          JWT-клиент: вход, выход, одно общее обновление токена на пачку 401
  opeka-api.ts    вызовы /api/v1/prosecutor-opeka/
  store.ts        сессия и снимок рабочего пространства; mutate() = вызов API + перезагрузка снимка
  access.ts       правила ролей — только чтобы показывать и прятать кнопки (решает сервер)
  views.ts        выборки из снимка: фильтры реестра, KPI, сигналы, задачи
  files.ts        проверка файла перед загрузкой, скачивание и предпросмотр
components/       AppShell (меню, состояния сессии), login/, Modal, формы, карточка дела, экраны
app/              маршруты: /login /overview /registry /registry/[id] /signals /tasks /users /settings
tests/            vitest: выборки и правила интерфейса на демо-наборе (tests/seed.ts)
```

Сервер отдаёт снимок всего, что видит роль. Экраны строят из него свои представления, а изменения отправляют в API и перечитывают снимок. Фильтр реестра и вкладка карточки хранятся в URL (`/registry?filter=late`, `/registry/2?tab=comments`).

## Проверки

```sh
yarn test              # тесты выборок и правил интерфейса
yarn lint
npx tsc --noEmit       # перед первым запуском: npx next typegen
```

Бизнес-правила проверяются тестами бэкенда: `python manage.py test auth prosecutor_opeka --settings=prosecutor_app.settings_test`.

**Сквозной сценарий в браузере** (`e2e/full-cycle.mjs`) проходит под каждой ролью весь цикл: создание и ведение карточки, замечания, передачу, архивирование, администрирование, права суперпользователя и отделение от ДТП. Он работает с живыми фронтом и бэкендом и создаёт записи «ТЕСТ Е2Е …», поэтому запускайте его на тестовой базе или удаляйте записи после прогона:

```sh
E2E_ACCOUNTS='{"admin":"…","opeka.insp.almaly1":"…",…}' node e2e/full-cycle.mjs
```
